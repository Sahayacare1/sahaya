# 2026-09-13

## SAHAYA marketing site — full UI audit and rebuild

Reviewed every section of the Next.js 16 / Tailwind v4 / GSAP site and rebuilt the
ones that were broken or weak. Verified with `tsc`, ESLint (0 errors, 0 warnings),
a production build (all 6 routes prerendered) and headless-Chrome screenshots at
desktop (1440) and mobile (390) widths.

### Correctness bugs fixed

- **`PageHero` had no scrim at all.** Scrim colours were built by concatenating an
  alpha suffix onto a CSS variable — `var(--color-teal-ink)` + `"b3"` — producing
  the invalid value `var(--color-teal-ink)b3`. The browser dropped the declaration,
  so inner-page hero copy sat on bare photograph. Replaced with a `color-mix()` helper.
  Also switched to a vertical scrim below `lg`, because the copy spans the full width
  on small screens and a horizontal gradient cannot carry it.
- **`DayStory`'s sticky photo column was inert.** `html`/`body` both had
  `overflow-x: hidden`, which makes the other axis compute to `auto` and turns the
  element into a scroll container — which breaks `position: sticky` for descendants.
  Changed to `overflow-x: clip`. The panel now pins and the photo swaps correctly.
- **`ServiceSelector`'s "curtain wipe" was never implemented.** Built it. Also
  removed a scroll-scrubbed GSAP tween and a GSAP hover tween that both wrote
  `scale` to the same `<img>`, so the hover was overwritten on every scroll tick.
- **Build failed** on the server/client boundary: route pages are server components
  (for `metadata`), and they passed Lucide *component references* through props to a
  client component. `ServiceGrid`/`DayTimeline`/`PhotoCTA` are server components now.
- **`Reveal` could hide content permanently.** It rendered `opacity: 0` and relied on
  GSAP. Added three independent escape hatches: `no-js` CSS, a reduced-motion block,
  and a watchdog timer inside `Reveal`.
- **Inner pages had no `metadata`** — all four were `"use client"` pages. Converted
  to server components; each route now has a title, description and canonical.
- **Headlines read as gibberish** to screen readers: one `<span>` per word with no
  whitespace, spacing faked with margin ("Yourchild is safe."). Now an `aria-label`
  with the real sentence plus `aria-hidden` visual lines.
- **Enquiry form:** no `htmlFor`/`id` on any label, no validation, no error messaging.
  Rewired all six fields, added validation, inline errors and an `aria-live` status.
- **Stats contradicted the FAQ** — the strip claimed "3 Cities" while the FAQ said
  Hyderabad only. Figures moved to `lib/constants.ts`.
- Marquee hid its own trust claims behind `aria-hidden` and jumped at the loop seam.

### Consolidation

`PageHero`, `DayTimeline`, `ServiceGrid`, `PhotoCTA` extracted. The hero alone had
been copy-pasted into four route files as a ~90-line function. Deleted three dead
files that referenced a palette that no longer exists (`SectionHeader`,
`MomentStrip`, `lib/gsap.ts`).

### Design system

Rewrote `globals.css`: `@theme` with literal values (note `@theme inline` cannot
reference other variables), fluid type ramp (`.t-display`/`.t-h2`/`.t-h3`/`.t-lead`),
section rhythm helpers (`.section`, `.dark-seam`), `--nav-h` tokens, `.btn-sm`/`.btn-lg`
/`.btn-ghost` variants replacing `!important` override soup, night-surface card and
field variants, and global `:focus-visible` styling.

Gave the page a deliberate light/dark rhythm. DayStory and HowItWorksPreview were both
near-black and butted together, reading as one slab; they are now distinct tones with a
seam. Testimonials sits on a deeper ivory so it does not merge with TrustSection.

## Follow-up pass

### Branded 404

`/does-not-exist` was serving the **raw Next.js default** — a system-font
"404 / This page could not be found." with inline styles, dropped inside the SAHAYA
navbar and footer. Added `src/app/not-found.tsx`: calm copy, on-brand colours, two
CTAs and links to every section, so a 404 routes back into the site.

### The fail-safe had a hole

The original three layers only covered *JS disabled* and *React hydrated*. The case
that was still unhandled: **JS enabled but React never hydrates** (a chunk 404s, a
hydration exception). The inline script removes `no-js` on load, so the `no-js` CSS
layer stands down, and `Reveal`'s watchdog lives inside `useEffect` — so it never
runs either. Result: every `.js-reveal` element stuck at `opacity: 0` forever.

Fixed with a handshake:

- `layout.tsx` inline script starts a 3s timer that force-reveals `.js-reveal`
  unless `window.__sahayaHydrated` is set.
- `Reveal`'s effect sets `window.__sahayaHydrated = true` on mount.

So the fallback fires only when React genuinely failed, and does not flatten the
animations when hydration succeeded.

Verified by blocking `*/_next/static/chunks/*.js` via CDP `Network.setBlockedURLs`:
10 reveal elements, **0 hidden**, and the TrustSection screenshot renders fully.
Note: blocking `*/_next/static/chunks/*` also blocks the CSS (same path) and makes
the test meaningless — block `*.js` specifically.

### Dead code removed

`ScrollImage.tsx` became unused when TrustSection was rewritten with a plain
`<img>` that stretches to the card grid's height. Deleted, along with the stale
`.js-hide` CSS utility and the comment referencing it.

### Nav breakpoint

The nav links were hidden until `lg` (1024px), so an 834px iPad portrait got a
hamburger despite having room for four short links. Moved to `md`, with padding
tightening at `md` and relaxing at `lg`. Measured at 390/700/767/768/834/1023/
1024/1280/1440px: handoff is exactly 768px, no wrapping, header stays 72px, no
horizontal overflow at any width.

### Design token note

When a component needs a translucent version of a colour that may be a CSS
variable, use `color-mix(in srgb, X N%, transparent)` — never string-concatenate
an alpha hex onto it. See the `tint()` helper in `PageHero.tsx`.

## Performance + a11y pass

### LCP: the hero photo was discovered last

Every hero photo is applied as a CSS `background-image`, so the browser cannot
start fetching it until the stylesheet has parsed and the element has been styled
— by which point the fonts and other work are already queued. Added a hoisted
`<link rel="preload" as="image" fetchPriority="high">` to `Hero` and `PageHero`
(React 19 hoists it into `<head>`).

### A competing preload was cancelling it out

Next.js auto-emits a preload for any `loading="eager"` image. `DayStory` marked
its **first** scene eager, so the home page shipped a preload for
`story-dropoff.webp` — an image ~1900px down the page that is not the LCP
element — competing for bandwidth with the actual hero photo. Made every DayStory
scene lazy; the panel is far below the fold so nothing there should be eager.

Result: each route now preloads exactly one image, its own hero.
`/` → hero-background, `/how-it-works` → trust-caregiver, `/child-care` →
child-care, `/elder-care` → elder-care, `/about-contact` → hero-background.

### Anchors hard-jumped

The "See a typical day" links on the service pages (and the skip link) jumped
instantly, because Lenis was not told to handle anchors — which reads as broken
on a site that smooth-scrolls everywhere else. Set `anchors: { offset: -80 }` so
the scroll animates and the target heading clears the fixed navbar.

### Audit results (all clean)

Heading hierarchy: exactly one `h1` per route, **no level skips** on any of the
five routes. Reduced motion (emulated via CDP): reveals present, **0 hidden**,
Lenis correctly not initialised, marquee animation `none`. Keyboard focus: tab
order is Skip link → logo → nav links, **0 stops without a visible focus ring**.
Anchor: scroll animates (mid-flight 483 → final 519), target lands 140px from the
top with the navbar at 60px, so it clears.

- `WHATSAPP_NUMBER` = `919999999999` (placeholder; every CTA is dead).
- `public/` ships ~15.9 MB of unreferenced source PNGs (eight `ChatGPT Image…png`
  at 1.9–2.4 MB each) plus a root-level 168 KB `.webp`. They are the source files
  the WebP derivatives came from. Not deleted — they are the user's assets.
- Nothing is committed.
